# 1.0.11（12）只对真实音频提供播放与转文字

本版纠正此前对“语音回复”的扩展理解：普通文字不需要合成语音。

- 移除每条 AI 普通文本后的「语音回复」按钮。
- 移除顶部自动朗读开关和完成回复后自动 TTS 的执行路径。
- 只有音频附件（audio/* 或音频扩展名）以及 Markdown 中明确指向本地/同源音频文件的链接，显示音频卡片。
- 音频卡提供播放/停止、下载，以及新增的「转文字」。普通文本、普通文件不会出现「转文字」。
- Markdown 音频链接直接渲染为相同音频卡，转文字结果留在该卡片下方，可复制、收起/展开，不写入聊天历史、不作为消息发给 AI。
- 转文字只在用户点击后执行：检查当前 Profile 的 STT 配置 → 鉴权流式下载音频 → 按真实文件名和 MIME 上传至官方 STT 接口。现成音频播放仍不需要 TTS。
- 未配置 STT、音频过大、服务返回错误均明确提示并可重试。可取消，切聊天/Profile、退出/后台取消并丢弃迟到结果，临时文件清理。
- 识别结果仅在内存按聊天/音频缓存最近 16 项，退出/Profile 切换清理；再次打开 App 可重新转文字。识别结果仅供参考。

## 大小与权限

保留大文件下载逻辑，不恢复 25 MB 下载上限。音频转文字受官方 STT multipart 总量 50 MB 限制，本地音频设 49 MB 以预留 multipart 开销；这不限制单独播放或保存文件。

通过当前 Studio 服务端配置的 STT 处理音频（可能使用配置的第三方识别供应商），不自动录音、不请求麦克风权限、不把普通文本发送到 TTS。

## 验证边界

单元/Widget 测试覆盖普通文本无语音按钮、音频卡播放和转文字、MP3 文件名/MIME、STT 而非 TTS 请求、识别结果缓存、错误重试/取消、Markdown 普通文件链接仍能下载。

本机没有已连接手机；原生播放/系统保存/实际识别准确率需真机验收。聊天恢复重复/闪动问题仍在排查，不在本版修复范围内。

本轮结果：静态分析无问题，159 项本地测试通过（7 项环境测试默认跳过）；6 项隔离服务端真实 HTTP/Socket.IO 测试通过，其中补验了远端音频附件下载后上传 STT 并返回文字的完整链路。识别服务使用确定性夹具，不代表实际识别准确率。
