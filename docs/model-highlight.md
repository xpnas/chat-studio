# 模型高亮越界与聊天空间调整

## 现象与原因

用户截图中模型列表向上滚动后，浅绿色高亮进入了「选择模型」标题和搜索框区域。这不是模型选择状态错误，而是绘制范围问题。

旧 `model_sheet.dart` 给 `ListTile` 设置了 `selectedTileColor`，但条目自身没有 Material。ListTile 的背景在最近的祖先 Material 上绘制；本例是整个模态弹层的 Material。选中条目移出滚动视口、仍保留在 ListView 的缓存范围内时，高亮会跟随条目坐标画到列表以外。仅给 ListView 设置裁剪或调整排序不能保证这个背景被裁剪。

## 修复

- 每个惰性构建的模型条目包裹独立圆角 Material，并设 `clipBehavior: Clip.antiAlias`。
- 选中背景由条目自己的 Material 负责；ListTile 的 `selectedTileColor` 为透明，不再向整张弹层绘制选中色。
- 保留 `selected` 语义、「当前使用」文字、勾选及字重，不通过关闭选中状态掩盖问题。
- 列表显式使用 `Clip.hardEdge`；涟漪/按压高亮同样限制在条目自己的 Material 内。
- 保留提供商分组、当前模型置顶、展开/折叠、搜索、选择回传。列表仍惰性构建，不一次创建全部模型 Widget。

## 可以复现旧问题的测试

`test/chat_spacing_model_paint_test.dart` 包含 6 项回归：

1. 浅色主题：100 个模型，依次滚到 120 / 160 / 220 / 350 / 1800，再滚回；截取整张实际弹层图像中固定标题/搜索框的原始 RGBA 像素，要求与初始帧完全一致。
2. 深色主题执行相同像素验证。
3. 当前项仍具有选中语义和局部裁剪；折叠、展开、搜索其他提供商再清空时，选中状态没有残留或丢失。
4. 按住条目、保持 ink 高亮并改变滚动位置，确认标题区仍未被绘制。
5. 390 宽、正常字体下检查气泡边界/内边距和用户、AI 实际字体样式。
6. 320 宽、1.8 倍系统字体下检查相同布局和字号，没有渲染溢出。

本地曾临时恢复修改前的模型列表实现，浅深主题的两项像素测试均失败；恢复本次修复后全部通过。这是对实际绘制的回归，而非仅检查 `selected` 的布尔值或手工截图观察。

## 内容空间与字号

- 聊天内容左右外边距从 20 → 10，约减半；垂直外间距从 6 → 5。
- 气泡水平内边距 14 → 11，垂直内边距 10 → 8，圆角 20 → 16；仍保留淡色背景区分用户/AI。
- 普通正文共享样式字号从 14.5 → 15.5，行高保持 1.48，系统文字缩放继续生效。
- Markdown 标题/粗体/等宽代码保留语义层级；不是把辅助工具、思考过程和输入框都一并放大。
- 单侧正文总留白从 34 减少到 21，在相同手机宽度下给文字多提供约 26 逻辑像素宽度。宽屏气泡最大宽度约束保持不变。
