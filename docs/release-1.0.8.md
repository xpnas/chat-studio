# 1.0.8（9）审批、排队、首次发送与语音回复

## 审批

- resolved=false 且非 stale 时保留卡片和服务端错误，恢复重试；只匹配当前审批 ID，不让旧回执移除新卡片。
- 提交后禁用重复提交，15 秒未收到回执显示状态待核对，不自动重发。
- 按 requested_at/timeout_ms 或 remaining_timeout_ms 判断过期，定时禁用按钮；重复 requested 不延长有效期。
- 仅当服务端 choices 包含 always 且 allow_permanent=true 时显示永久允许，二次确认后发送 always。作用范围/持久化/撤销仍由服务端决定，不提供伪造客户端白名单。

## 队列

- 当前运行已经 started 后，输入新消息可加入服务端队列，支持附件。仍然禁止离线/恢复中提交，不做断线自动重发。
- 队列消息独立展示发送中/排队中/待同步/失败，使用官方 run.queued、queued_messages、dequeued_queue_id 和 resume.queueMessages 同步；取消使用 cancel_queued_run，不提前从界面移除。
- 等待队列不插入正在流式输出的 assistant 中间；出队后再出现用户消息。完成时队列未清空不触发覆盖历史的早期分页请求。
- 本轮提供追加/显示/取消；Web 的“插入当前执行”高级控制未接入。

## 首次发送

发现并修复“首次发送尚未 run.started，旧活动快照已触发 resume”的竞态路径：等待首次回执时不主动恢复未完成创建的会话，过滤早于当前提交时间的活动事件。超时仍保留不确定状态，再恢复核对，绝不自动重发。

迟到历史请求失败现在也检查 requestId，避免已被 resume 作废的请求给新视图提示错误。这修复可重现时序问题，不保证所有供应商/网络错误都由此产生；真实生成失败仍展示错误。

## 语音回复

- AI 回复有手动语音按钮，顶部扬声器开关开启当前会话自动朗读；仅朗读前台会话的新完成回复，不朗读思考过程和工具输出，不重连重播历史。
- 通过官方 POST /api/studio/tts/synthesize 使用当前服务端 Profile/用户的 TTS 配置，手机不接收供应商密钥。需先在 Web 配置 TTS。
- 合成中可取消，播放中可停止；一个 App 仅有一个音频播放器，切聊天/Profile、退出或进入后台停止播放。
- 文本 12000 字符、音频 20 MB、60 秒超时限制，鉴权失败、格式无效和网络错误明确提示。
- 此实现是“文本回复完成后合成语音”，不是模型原生实时双向音频。

## 验证边界

本地 Widget/协议测试不能替代真实手机音频输出、来电音频焦点和蓝牙路由验收；未连接真机。本地服务测试使用确定性模型/音频夹具，不代表真实发音质量。GitHub iOS 构建与 Apple 签名仍需远端执行。
