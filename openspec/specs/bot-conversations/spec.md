# bot-conversations Specification

## Purpose

让用户在手机上使用当前账号已配置的 BOT，继续已有对话、了解后台任务进展、处理需要人工决策的持久交互并追问结果，同时保持 BOT 身份、执行资源和不同账号之间的数据隔离。

## Requirements

### Requirement: BOT 列表遵守账号所有权
客户端 SHALL 提供已配置 BOT 的搜索、分页和打开入口；BOT 身份 SHALL 与普通 Ekko/Coding Agent 和私有 worker 会话区分，并遵循账号所有权及服务端资源权限。

#### Scenario: 普通会话列表出现 Person 主会话
- **WHEN** 记录属于 Person BOT 而 agent 字段为 ekko-agent
- **THEN** 客户端按 BOT 路由打开，不按普通 Agent 会话启动新上下文

#### Scenario: 改变普通聊天的 Profile
- **WHEN** 用户切换普通聊天 Profile
- **THEN** BOT 列表不被当成该 Profile 的普通会话列表，不自动修改 BOT 配置；资源权限仍由服务端校验

#### Scenario: 切换账号
- **WHEN** 用户退出并登录另一账号
- **THEN** 旧 BOT 列表、正文、协作缓存、草稿及迟到回包均不可进入新账号视图

### Requirement: BOT 对话沿用已保存配置
客户端 SHALL 在原 BOT 主会话中发送、停止当前主会话运行和恢复对话，保留服务端模型、工作区及执行配置；普通新建聊天偏好 SHALL 不覆盖 BOT 配置。

#### Scenario: 从 Web 继续 BOT
- **WHEN** 手机打开 Web 已配置并使用的 BOT 后发送消息
- **THEN** 消息继续原 BOT 会话，普通 Agent 模型偏好不改变其运行配置

#### Scenario: 主会话停止但后台任务仍存在
- **WHEN** 主会话停止后服务端仍报告后台任务运行
- **THEN** 界面分别显示主会话与后台任务状态，不将前者停止描述为全部协作已停止

### Requirement: 进展和结果区分不同状态
客户端 SHALL 展示主会话、后台任务、执行和协作各自的服务端状态，以及可见结果和授权附件；断线、working=false 或任务列表刷新 SHALL 不被解释为全部工作成功。

#### Scenario: 后台任务等待用户
- **WHEN** 主会话空闲但后台任务等待审批或回答
- **THEN** 手机保留待处理入口和状态，不显示全部完成

#### Scenario: 结果含附件
- **WHEN** 授权投影包含任务结果及文件引用
- **THEN** 用户可查看结果和通过受权路径打开附件，失效或无权限时显示明确原因

### Requirement: 持久审批和澄清按版本处理
客户端 SHALL 支持服务端返回的 BOT 审批及澄清，按对应交互标识和版本提交；durable 交互 SHALL 不自设倒计时，也不提供服务端禁止的永久授权。

#### Scenario: 另一端已经回答
- **WHEN** Web 已回答或执行已使交互过期
- **THEN** 手机提交被拒绝后刷新并禁用过期项，不自动授权新交互或重发旧回答

#### Scenario: 重连恢复持久问题
- **WHEN** 手机重连时收到仍待处理的 durable 问题
- **THEN** 问题重新显示且保留服务端选择范围，不因本地时间经过而自行过期

### Requirement: 任务追问绑定正确执行
客户端 SHALL 允许查看 BOT 任务的当前及历史执行，并通过任务专用路径提交明确的追问和停止操作；执行标识、任务版本和幂等键 SHALL 遵循服务端契约，私有 worker SHALL 不成为普通会话入口。

#### Scenario: 阅读旧执行后追问
- **WHEN** 用户正查看历史执行而当前执行已变化
- **THEN** 客户端明确追问目标和当前状态，按服务端前提提交或提示冲突，不把文字投递给旧 worker

#### Scenario: 追问已提交但确认丢失
- **WHEN** 网络断开导致结果未知
- **THEN** 客户端恢复任务与待处理输入状态，不自动创建第二个追问；用户明确重试同一操作时保留原幂等键和原始负载

### Requirement: BOT 必须提供完整可恢复的历史
客户端 SHALL 只在 BOT 对话与协作统一时间线、详情和恢复行为共同通过验收后开放完整 BOT 功能；缺少必需协议时 SHALL 明确限制功能，不以普通消息分页伪装完整协作历史。

#### Scenario: 只有协作卡片的历史页
- **WHEN** BOT 历史页没有普通消息但包含协作结果
- **THEN** 用户仍看到这些结果并可继续翻页和打开详情

#### Scenario: 服务端不支持 BOT
- **WHEN** 已确认 Person 接口不存在
- **THEN** BOT 入口说明能力限制，已有普通聊天继续可用，不自动创建替代 BOT
