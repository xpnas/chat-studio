# studio-compatibility Specification

## Purpose

为移动客户端连接不同版本的 Studio 定义可验证的兼容范围，使新增 Agent、模型和状态同步能力能够逐项启用，同时保留旧服务端核心聊天，并明确暴露鉴权、网络和协议错误。

## Requirements

### Requirement: 固定版本的兼容验收
客户端发布 SHALL 同时验证已登记的旧基线与 v0.8.21 稳定基线；主分支专有 Agent 增强 SHALL 使用单独登记的固定提交验证，且不得替代稳定版验证。

#### Scenario: 双基线核心聊天验收
- **WHEN** 执行发布兼容检查
- **THEN** 每个正式基线均实际执行登录、Profile 隔离、发送、停止、恢复、历史分页、附件与群聊的适用检查，并记录精确 commit 和执行结果

#### Scenario: 上游测试文件缺失
- **WHEN** 某基线不存在旧测试入口或实际没有执行任何测试
- **THEN** 检查 SHALL 失败或明确报告未验证，不能作为兼容通过

#### Scenario: 插件能力缺少预览验证
- **WHEN** 稳定版核心检查通过但固定预览提交的插件 Agent 验证未通过
- **THEN** 发布 SHALL 保持插件 Agent 增强关闭并说明未验证范围，不能标注该增强已兼容

### Requirement: 能力协商保留错误语义
客户端 SHALL 依据接口或协议的实际支持状态选择路径，且 SHALL 区分不支持、未认证、无权限和暂时不可用；版本显示文本不得作为唯一判断条件。

#### Scenario: 新接口明确不存在
- **WHEN** 已认证的服务端明确返回新的可选 Agent 接口不支持或不存在
- **THEN** 客户端使用既有 availability 路径并继续提供已验证的核心聊天

#### Scenario: 新接口暂时失败
- **WHEN** 新接口超时、返回 5xx 或非预期响应结构
- **THEN** 客户端显示可重试状态，不永久记录为旧服务端，不把未验证的缓存标为最新可用

#### Scenario: 鉴权与权限失败
- **WHEN** 请求返回 401 或 403
- **THEN** 客户端分别处理登录失效或权限不足，不通过另一个接口绕开限制

### Requirement: 协议状态按连接身份隔离
客户端 SHALL 将能力、目录和异步结果限制在服务器、账号、资源范围及当前连接/请求世代内；普通会话按 Profile 隔离，Person 按账号/BOT 所有权并核验资源权限，更换身份后旧结果不得影响新范围。

#### Scenario: 切换 Profile 时旧请求完成
- **WHEN** 用户切换 Profile 后原 Profile 的模型或 Agent 请求才返回
- **THEN** 旧结果不改变当前选项、当前错误状态或当前会话配置

#### Scenario: 服务端升级后重试能力探测
- **WHEN** 用户重新登录或显式刷新已变化的服务端能力
- **THEN** 客户端允许重新探测原先缺失的能力，不要求清除全部应用数据

### Requirement: 恢复不得重放写操作
客户端 SHALL 在前台恢复或网络重连时恢复服务器状态，而非自动重发 run、停止、审批、模型修改、任务写入、删除、追问或协作创建/控制请求；支持幂等键的操作 SHALL 保持键与原始负载对应，明确重试前先对账。

#### Scenario: 发送后断线且结果未知
- **WHEN** 发送请求已交出但客户端未收到确认就断线
- **THEN** 重连查询/恢复原会话并显示待同步状态，不再次发送原用户消息

### Requirement: 兼容验证使用隔离环境
协议验证 SHALL 使用独立测试账号、数据库、Profile 和工作区，验证精确检出提交，并清理自己启动的服务进程；验证 SHALL 不依赖生产凭据或更改用户真实会话。

#### Scenario: 提交不匹配
- **WHEN** runner 收到的上游工作目录不属于选定基线 commit
- **THEN** runner 在启动服务或写入测试数据前拒绝执行

### Requirement: 分阶段完成不能替代完整协作验收
客户端 SHALL 分别记录核心、任务与消息、BOT 对话与协作阶段的验收结果；整个变更完成 SHALL 包含稳定版真实双客户端 BOT 协作闭环、旧版能力缺失处理及移动界面检查，不能只凭核心阶段通过而宣告完成。

#### Scenario: 核心已发布但 BOT 尚未通过
- **WHEN** 阶段 A 已通过但 BOT 时间线或协作控制仍有未完成项
- **THEN** 核心功能可发布，完整 BOT 功能保持关闭，变更任务仍显示未完成

#### Scenario: 旧版没有新增业务接口
- **WHEN** legacy 明确不支持任务清单、消息编辑或 Person
- **THEN** 各入口准确说明能力限制且核心聊天可用，不以降级通过声称旧版支持 BOT 协作

#### Scenario: 只有模拟协作测试通过
- **WHEN** 仅固定协议样例通过，真实 Studio 执行环境不可用，或未完成已批准范围内的 BOT 闭环
- **THEN** 报告区分协议验证与真实执行，相关完整协作验收保持未完成

#### Scenario: 本次批准的本地受控模型验收
- **WHEN** 本次变更按用户于 2026-11-13 批准的范围，使用本地受控模型执行固定 stable Studio 的双客户端 BOT 闭环
- **THEN** 验收核对真实工具执行、持久交互、结果附件、追问、顺序/并行协作、有限轮次、停止/恢复和历史，并明确记录真实模型未验证；不得用预制 Socket 事件或仅协议 mock 代替服务端执行
